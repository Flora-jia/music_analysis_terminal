# PS 音符事件层上板测试总结

**日期**：2026-10-30
**被测对象**：`audio_note_events.elf`（PS 音符切分阶段 A + 谱通量起音阶段 B）
**硬件基线**：PL-2 固定 bit（`audio_top_overlap4096_h512.bit`，4096 点窗 / hop=512 / 约 31.25 fps）
**启动配置**：`Debugger_audio_app_new-PL2_NoteEvents`
**输入链路**：PC 音频线 → AC820 LINE IN，播放 16 kHz 单声道合成 WAV
**代码状态**：本次测试期间**未修改任何代码**

---

## 1. 测试目标与范围

### 1.1 目标

验证新 PS 音符层能否把“每帧一个音高”转换成可用的 `note_on / note_off` 事件，重点检查：

1. 持续音是否只产生一个音符；
2. 换音是否按顺序切分；
3. 同音重复是否能拆成不同音符；
4. 渐强、颤音等连续变化是否被误判为“又弹了一下”；
5. 事件时间戳、音符编号、简谱映射是否正确；
6. 计算开销与数据完整性是否可接受。

### 1.2 范围

- **包含**：启动链路、静音拒绝、音阶、同音重奏、渐强、颤音、事件级日志、性能统计。
- **不包含**：真实乐器、150 ms 起音级快音、250 ms 分档、混音/复音、AI 分类、LCD、UART 二进制事件协议。

## 5. 现象解释

### 5.1 音符时长为何是 608 ms，而不是 500 ms

音阶的每个音是被**下一个音的起音边界（CHANGE）**关闭的，所以时长 = 500 ms 音符 + 100 ms 间隔 + 过渡 ≈ 608 ms。同音重奏同理（含 200 ms 间隔，约 700 ms）。

根因是 **4096 点窗 = 256 ms**：声音停止后，窗内能量仍需约 256 ms 才能衰完，`quiet` 无法在 100 ms 间隔内触发，只能等下一个音“顶掉”。

> 结论：这是窗长的物理限制，不是计时或状态机错误。报告应使用“hold until next attack”的描述，不能把该时长当作发声响时长。

### 5.2 为什么多数音符以 `PITCH_LOST` 收尾

本次 `cal=0`，静音门限使用固定 `-70 dB + 3 dB = -67 dB`。音符停止后，能量在窗内缓慢衰减，尚未跌到 -67 dB，YinFFT 已连续 3 帧判无效，因此先触发 `PITCH_LOST`。

### 5.3 为什么校准显示 `cal=0`

校准结果只保存在 RAM，**重新 launch 后即丢失**。本次在测试前重新启动过，因此校准状态被清除。后续每次 launch 后必须重新校准。

### 5.4 `unassign` 偏高的原因

6 个音共产生 23 个 onset（其中 17 个未分配）。主要来自音符切换时窗内前后两音共存，谱通量出现多个峰；当前阈值偏敏感。暂不影响主流程，但会增加无效起音。

### 5.5 `gap` 每次换曲 +1

换文件时存在暂停/断点操作，导致帧序号不连续。测试期间稳态不增长，属人为操作影响，不是链路丢帧。

### 5.6 颤音测试的有效性存疑（重要）

日志显示：

```
NOTE ev=ON  id=13 ... start=0xC5BC00
NOTE ev=OFF id=13 ... end=0xC5CA00  dur_ms=224
（中间连续多帧 gate=1、max=0，约 0.86 s）
NOTE ev=ON  id=14 ... start=0xC60000
```

- 离线检查 `test_audio/vibrato_440.wav`：5.0 s 中只有首尾各 1.0 s 静音，**中间 1～4 s 连续**，不存在断口；
- 板端却在中途收到 `max=0`（频谱全零），说明 **LINE IN 当时确实没有信号**；
- 因此这次的两段音符，很可能是“播放被暂停/中断”造成的，而不是算法把连续颤音误切。

**结论：本次颤音结果不能用于判定 REATTACK 是否误触发，必须复测。**

## 6. 发现的问题与待改进项

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| P1 | 颤音段出现 2 个音符，但中间有约 0.86 s `max=0`，WAV 本身连续 | 结果不可判定，不能确认是算法误切 | **先复测**：播放期间不要暂停，确认 `max` 始终 > 0；若仍被切分，再收紧 REATTACK（判据改“且”、最小音长 300 ms） |
| P2 | 重新 launch 后校准丢失（`cal=0`） | 收尾走 PITCH_LOST，门限不准 | 每次 launch 后固定执行校准；启动时打印提示 |
| P3 | `quiet` 使用“噪声底 +3 dB”，数字静音下几乎不触发 | 音符无法按静音正常结束，时长含间隔 | 改为相对门限（本音峰值 −20 dB，下限 −55 dB） |
| P4 | `unassign` 偏高（23 onset / 6 音符） | 无效起音多，统计噪声大 | 观察是否需要把 `onset_alpha` 3.0 → 4.0 |
| P5 | 时长语义含音间间隔 | 报告数据易被误解 | 明确写为“hold until next attack”，并同时给出 ON 间隔 |
| P6 | 32 ms 更新 ≠ 32 ms 延迟 | 短音仍被 256 ms 窗混合 | 继续推进短窗起音支路；本轮不宣称 150 ms 通过 |

## 7. 简要结论

1. 阶段 A/B 在板上**基本可用**：音阶数量与顺序正确、同音重奏能拆成独立音符、渐强不误触发、计算开销可忽略。
2. 同音重奏 3/3 全部为 `REATTACK` 且使用新 `note_id`，说明**谱通量起音与音高关联链路已经打通**，这是本次最重要的成功项。
3. 尚未达到“全场景可靠”：**颤音场景结论待定**——日志中间出现约 0.86 s 完全静音，而 WAV 本身连续，疑为播放中断，需复测后才能判断是否存在 REATTACK 误触发；音符收尾时机则确实受 256 ms 长窗限制。
4. 本轮**未验证** 150 ms 快音、250 ms 分档、真实乐器与混音场景，不能对外宣称已通过。
5. 相对旧版的意义：系统从“每 32 ms 报一个音高”跨到“有起止、有编号、可配对的音符事件”，这是生成简谱的必要前提。

---

## 8. 后续建议

1. **先复测颤音**：整段播放期间不要暂停/切歌，确认 `PITCH ... max` 始终大于 0；若复测仍被切成两个音，再把 REATTACK 判据改为“能量升高 ≥3 dB **且** 此前有 ≥6 dB 衰减谷”，并增加“当前音已持续 ≥300 ms”和“最小间隔 ≥300 ms”。
2. **调整静音判据**：用相对门限替代“噪声底 +3 dB”，使正常停音能走 `QUIET`。
3. **固化测试流程**：每次 launch → 校准 → 确认 `cal=1` → 再播放测试音。
4. **回归四首**：颤音应为 1 个音、同音重奏仍为 3 个音、音阶仍为 6/6。
5. **再扩展测试**：真实乐器（钢琴/吉他/小提琴样本）、500/250/150 ms 分档，按“漏音、错音、多音、八度错、边界误差”分别统计。
6. **统计口径**：以 `frame` / `first_sample` 对齐播放起点；不要用“音符个数出现过”代替准确率。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| `NOTE_ON` / `NOTE_OFF` | 音符开始 / 结束事件 |
| `REATTACK` | 同音高再次起音（同音重奏） |
| `CHANGE` | 换到不同音高，旧音在边界处关闭 |
| `QUIET` | 因信号安静而结束 |
| `PITCH_LOST` | 仍有声但连续无法追踪音高，结束并标不确定 |
| `tq` | 时间质量：0 窗口估计、1 起音估计、2 截断 |
| 256 ms 窗 | 4096 点 / 16 kHz 的分析窗长度；32 ms 只是更新间隔 |
