# 观察到的错误与最小排查

| 触发条件 | 排查动作 | 何时停止下结论 |
|---|---|---|
| 峰值相同但怀疑拼帧 | 用不同源帧载荷或带golden_values逐点比较 | 仅同峰不能证明其余频点正确 |
| 停收后帧号跳变 | 核对所有包还是抽样日志、丢帧计数、首样本差 | 打印节流造成的跳号不算DMA漏帧 |
| valid被ready压住 | 测试台保持ready低，断言data和TLAST稳定 | 包级JSON不能取代该握手断言 |
| 多使用者消费不同拍 | 统一fire条件或正确广播握手，各分支计数 | 不能将valid同时连接视为自动同步 |
| 首样本不按hop增长 | 对照源样本计数、环形缓存、窗口快照 | 只核对输出点数不足以证明连续输入 |
| 复位后首帧错位 | 核对DMA、FIFO及帧缓存复位边界 | 不靠丢弃前几个字凑齐包头 |

提示词模板（新整理，尚无独立提示词效果统计）：
> 给定【完整帧协议】【RTL】【固定点黄金数据】【慢接收日志】，先写出每次valid/ready fire的计数规则，再列同帧参考峰、载荷、TLAST、序号和丢弃的验收断言。实现对照工具并注入短帧/错bin/半包停顿/满bank。不要改变已有数值缩放来掩盖协议错误；不能验证的层级明确留空。
