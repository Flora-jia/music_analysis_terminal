# 移植步骤与排查顺序

1. 准备 PYNQ/内核/Python/NumPy版本、镜像来源、运行用户和驱动要求。保持已验证镜像；不要把使用其他Vivado版本直接解释为必须升级整个系统。
2. 从可信构建记录取得bit/hwh哈希，列出本项目需要的IP名称和地址。填写spec，不从示例复制地址。
3. 停止旧应用，核对一个硬件所有者；重新下载会使原MMIO/DMA对象失效，须重新初始化。Jupyter发现旧模块来源时先正常停止、重启内核。
4. 先禁用可控生产者，再配置缓冲与S2MM；高地址位、对齐、长度上限、simple/SG模式按实际IP核对。模板使用u4固定包，长度以字节提交。
5. 提交地址/长度后再启用生产者；接收超时分清无输入、DMA错误、长度/TLAST、生产者时钟和复位。不要把所有超时都归为模型慢。
6. 非一致性缓冲在提交前flush，CPU读取前invalidate；根据实际PYNQ Buffer API适配。读取后copy再交给慢消费者，不能一边覆盖一边绘图。
7. 停止时禁生产者→请求DMA停止→有限等待halted→线程退出/使用者释放→free。未确认时保留对象与缓冲并报告隔离状态。不要靠循环重置掩盖错误。

输出检查表应包含：版本与哈希、IP映射、实际接收长度、包校验、源时间轴、异常计数、停止结果。没有硬件执行时保留“未验证”，不填通过。
