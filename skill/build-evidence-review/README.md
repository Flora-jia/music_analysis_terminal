# 构建制品与时序证据核查

**适用范围**：Vivado文本报告与bit/hwh/源清单的交付核查，以及一般工程中“设计值、局部测试、最终实测”的证据分类。其他工具报告需更换解析器；不能只改文件名。

**用法**：先从可信构建保存制品和报告哈希，填写receipt。运行：

```bash
python scripts/audit_build.py --root examples/complete --spec examples/complete/receipt.json
```

默认严格检查约束覆盖。未知格式直接报未解析，不猜测通过。scripts/audit_build.py 读取全局WNS/TNS/WHS/THS、时钟表与约束缺项；不自动修改XDC或豁免路径。

**来源**：同目录有两个配置载荷不同的bit，而正式PYNQ入口又会重新下载；“Program Device加载过什么”不足以确认最终版本。正WNS/WHS报告仍有3个输入、25个输出缺外部延迟，不能称所有板级接口约束闭合。模型的87ms推理、32ms谱更新和一秒输入段也不能写成同一个端到端延迟。

**已验证效果**：历史归档用哈希绑定运行包与报告；本次工具重读真实时序报告能保留正裕量并指出IO缺项，注入负hold、错文件哈希或未知格式会拒绝通过。重打包曾在新目录校验253文件、22项主机检查通过；该历史结果不表示已全流程重新实现或上板。

**失效条件**：清单来源不可信、报告被裁剪、不同构建混用、未知工具格式、重建只做到创建工程、只有局部算法计时等，均不足以支持完整复现/性能结论。源到bit还需实际完整构建；约束豁免必须有接口依据，不能自动设置false_path。
